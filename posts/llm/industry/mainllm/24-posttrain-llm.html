RL 控制推理强度 ​

笔记

Systemp Prompt 引入标量强度级别

  • Reasoning Effort: {effort} (range 1--100; higher values request more thorough reasoning)
  • Max：100；high：75；low 50。

分强度采样

  • 对1个prompt，每个强度 b，分别采样 Mb个回答。

    zb,j∼πθ(⋅∣x,b),b∈B,j=1,⋯,Mb

  • 在同1强度内 计算GRPO优势；不同强度不做比较。

长度惩罚

  • 对回答 zb,j 奖励 增加长度惩罚项 rb,jlen，长度分量依赖强度b，

    rb,jlen=−min{Cmax,k(b)lb,jLnorm}

  • 符号定义

    • lb,j：推理token数

    • Lnorm：参考长度

    • Cmax：每条轨迹最多扣除的分数

    • k(b)：token惩罚系数，随请求强度指数下降，高强度允许长推理

      k(b)=kpexp⁡(−b−bminτ),τ=λΔb¯

异步后训练 Infra ​

样本级派发 (sample-level dispatch) ​

主要解决 rollout 长尾问题，这是训练瓶颈，核心，维持高rollout并发。

样本级调度 sample-level dispatch

核心

  • rollout 和 训练 放在同一物理设备，分时执行。无需手动调节 2阶段的资源分配。
  • 维持高 rollout 并发。

样本级派发 sample-level dispatch

  • 一个prompt可以派发多个组，即多个sample。
  • 但轨迹回收，只看达到 group size 即可，不用等同一个组所有样本全部收齐，不在乎来自哪个组。
    • 可我们的实现：1个 prompt，1次只派发1个sample，资源有限啊。
  • 稳定维持 rollout 并发量

缓解长度偏差和off-policy影响 ​

缓解长度偏差和off-policy影响

1. 长度偏差

  • 先收集的样本偏短，会改变数据分布。
  • 控制数据并发和舍弃部分过早短样本，处理偏差。

2. off-policy影响

  • 调节调度和训练样本条件，限制最大 off-policy 比例，保证训练数据不会过度偏离当前模型。
  • 训练加入 loss masking，移除staleness过高的token。

Interleaved Thinking

V3.2 丢弃工具推理，浪费token

  • 新User消息来时，会丢弃之前的推理，仅保留Tool Call 和结果；工具调用轮次，会保留推理。
  • 缺点：每次新 User 消息，都会清空推理，迫使模型从头求解，复杂 agent 流程，非常浪费token。

借助 1M 上下文，V4 改进

  • 工具调用场景：保留所有推理内容，不再清空，保留完整历史，使 Agent 任务更连续，持续累计思考。
  • 普通对话场景：新用户消息到来时，丢弃之前轮次推理，保持上下文简洁。
    • 即这些场景，保留思考收益有限。
Quick Instruction

背景

  • chat 场景，在回答之前，经常需要执行是否搜索、意图识别等辅助任务。
  • 传统方法：独立小模型处理，因为不能复用已有 KV Cache，而产生冗余Prefill

Quick Instruction

  • 专用 token： 附到输入序列，每个对应一项辅助任务，直接复用已计算KV，避免重复Prefill。

优点

  • 可并行生成搜索query、判断领域/权威性要求等，
  • 降低 TTFT 首token延迟
  • 免除额外小模型工程开销。

MOPD ​

多教师 OPD

OPD 来合版

  • 高效把专家知识 迁移到1个统一模型。
  • 学生πθ 采样训练轨迹，保持On-Policy学习；通过 logits 对齐 老师，Teacher 输出分布。
  • 整合各专家权重到一个参数空间，绕开权重合并或混合RL 性能下降的问题。
  • 10个 Teacher。

Reverse Full Vocab KL

  • 学生πθ 采样训练轨迹，保持On-Policy学习；通过 logits 对齐 老师，Teacher 输出分布。

  • N个专家 {πE1,…,πEN}，目标

    LOPD(θ)=∑i=1NwiDKL(πθ||πEi)

  • 全词表 KL 简化为 每个位置的 token 级估计，复用 RL 框架。

per-token 优势 (既有工作)

sg(log⁡πEi(yt∣x,y<t)πθ(yt∣x,y<t))
  • 缺点：梯度估计方差大，训练不稳定。未采用。

DeepSeekV4 方法

  • 全词表 logits 蒸馏，在反向 KL 中保留完整分布，获得稳定梯度，迁移专家知识。

DeepSeek-V3.2 摘要

参考链接

  • paper, 中文技术报告

问题背景

  • 开源和闭源差距越来越大，闭源模型性能提升很快 复杂任务能力很强。
  • 主要问题：架构长文本太贵太慢、后训练资源投入不足、Agent效果不足

核心方法

  • DeepSeekSparse Atteention：Ligntning Indexer 细粒度Token Topk选择器

  • DSA 2阶段预训练：2.1B Dense预热 + 943B Sparse预训练。

  • Scaling GRPO 算法

    • IS权重优化KL3估计、Mask异策略负样本、保持MoE路由和采样Mask 消除训推不一致。

  • 后训练：专家蒸馏 + 混合RL训练。

    • 设计工具调用+推理思考的上下文管理
    • 设计Search+Code+数学逻辑+代码工具+General四大Agentic任务构建过程

模型效果

  • DeepSeek-V3.2 在推理任务上的性能与 GPT-5-high 相近，略低于 Gemini3-Pro。
  • SWE-V、SWE-Verified和Terminal2.0：超过开源模型。

关键结论

核心贡献

  • 稀疏注意力架构

未来方向

  • 世界知识落后闭源模型：扩大预训练，弥补差距。
  • 复杂任务仍落后前沿模型：进一步完成基模和后训练流程。
  • Token效率提升：需更长上下文才达Gemini3-Pro效果。

Post-Train 流程 (单独训专家+蒸馏专家+MixedRL) ​

后训练概览

1. 单独训练8领域专家 (RL)

  • 单独训练8个领域专家模型 （从 DeepSeek-V3.2-Base 开始）
    • 写作、问答、数学、编程、逻辑推理、通用agentic任务、agentic编程、agentic搜索
    • 专家训练：都经过单独RL训练，各专家支持思考和非思考模式。

2. 专家生成数据训练Base模型 (SFT)

  • 用专家生成 长推理和直接回复数据，再用蒸馏数据 去训练Base模型
  • 后续再接下文的Mixed RL训练，通才单模型仅比多专才效果低一点点。

3. Mixed-RL 训练

  • 混合训练：推理+agent+人类对齐。GRPO算法。
    • 推理+Agent：Rule-Based奖励 + 长度惩罚 + 语言一致性奖励。
    • 其他通用任务：GenRM，每个任务有一个rubrics
  • 优点：平衡 不同领域性能，解决灾难性遗忘问题。

环境构建Agent

  • 数据准备：给定任务类别+Sandbox(bash+搜索)，Agent搜索数据并存入数据库。
  • 工具合成：Agent为任务合成工具，工具即函数。

    • 一致性检查：Solution结果必须通过验证函数校验，不断修改，直到通过为止。
  • 难度升级：迭代增加任务难度，更新解决方案、验证函数、扩充工具集。

数据筛选

  • 筛选出有难度可执行的优质任务，而非直接使用所有数据。

  • 使用DeepSeek-V3.2 解决100次，留下pass@100 > 0的任务。

RL Token 高效强化学习 (Toggle) ​

token 高效 背景

目标

  • 预算有限时，推理更有效率。
    • 希望 模型用简洁思维链，避免不必要 token 膨胀。不同题 不同 token 预算。
  • 预算充足时，能深入思考，真能提高效果。
    • 同时 遇到难题时，多思考真能提高正确率。

长度过拟合问题

  • 严格预算约束训练的模型，给更高token 也不能解决复杂问题，会采用截短的推理模式。
Toggle 交替训练方法

核心思想

  • 采用 2阶段，交替进行 限制预算训练 和 正常长推理训练。
  • 每隔 m 次迭代，切换训练模式。
  • 精简做对，充分思考把题做对，继续交替。

Phase 0：预算约束，学会精简推理

  • 定义：λ 掌握程度阈值， B(x) 该题预算，r¯(x) 平均奖励。

  • 对于某题

    • 还不会：正常奖励。
    • 已经比较会了：超预算 给0；不超预算，正常奖励。
    r~(x,y)={r(x,y),r¯(x)<λ,r(x,y)1{|y|≤B(x)}⏟成立为1,否则0,r¯(x)≥λ.

  • 确定每题预算B(x)

    • 收集该题的正确答案，取第ρ 百分位，比如中位数。

      B(x)=Percentileρ({|yi|:r(x,yi)=1})

    • 比如 正确回答长度是：[1000, 1500, 2000, 3000, 5000]，取中位数为 2000

    • 预算在训练前估计1次，后面保持固定。

Phase 1：正常训练，保留长推理能力

  • 原始奖励，不加预算约束。
  • 为何还要切回 Phase1？
    • 一直在phase 0，可能会过度适应短预算；
    • 切回 phase1，有机会探索更长有效推理。
